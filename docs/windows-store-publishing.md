# Publish AiFetchly through the Microsoft Store

AiFetchly uses the Microsoft Store MSIX distribution path. The GitHub workflow
creates an **unsigned** `.msix` submission package. Microsoft re-signs that
package after Store certification, so this path does not use a PFX certificate
or certificate password.

The existing signed MSI path remains available for direct downloads. Microsoft
does not sign MSI or EXE installers; Windows code signing in this repository is
currently optional (no certificate configured — see `docs/RELEASE_WORKFLOW.md`),
so direct-download production builds produce unsigned installers until
`WINDOWS_CERTIFICATE_BASE64` / `WINDOWS_CERTIFICATE_PASSWORD` secrets are added.

## One-time Partner Center setup

1. Create a Microsoft Partner Center developer account and reserve the AiFetchly
   product name.
2. Open the product in Partner Center and go to **Product management > Product
   identity**.
3. Copy these values exactly as Partner Center displays them:
   - Package/Identity/Name
   - Package/Identity/Publisher
   - Publisher display name
4. In the GitHub repository, open **Settings > Secrets and variables > Actions >
   Variables** and create:
   - `WINDOWS_STORE_PACKAGE_IDENTITY` = Package/Identity/Name
   - `WINDOWS_STORE_PUBLISHER` = Package/Identity/Publisher (normally starts
     with `CN=`)
   - `WINDOWS_STORE_PUBLISHER_DISPLAY_NAME` = Publisher display name

These values are public package metadata, so repository variables are preferred
over encrypted secrets.

## Build and submit

1. Open the **Manual Release Build** workflow in GitHub Actions.
2. Choose **Run workflow**, select `store`, and start the run. A push to
   `master` also creates the Store package.
3. Download the `electron-app-windows-store-...` workflow artifact and extract
   the `.msix` file.
4. Upload the unsigned `.msix` on the submission's **Packages** page in Partner
   Center. Do not sign it with a self-signed certificate first.
5. Complete the Store listing, pricing/availability, age ratings, privacy URL,
   declarations, and certification notes, then submit for certification.

The unsigned workflow artifact is for Partner Center submission, not direct
installation. After certification, customers receive Microsoft's signed copy
through the Store, and Store updates are managed by Microsoft. AiFetchly already
detects `process.windowsStore` at runtime and disables its GitHub updater for
the MSIX build.

## Microsoft Store Policy 11.16 — Live Generative AI Content

AiFetchly presents text, images, plans, artifacts, email templates, keyword
sets, and automatic replies dynamically generated by AI in response to user
input. This makes the product subject to [Microsoft Store Policy 11.16 — Live
Generative AI Content](https://learn.microsoft.com/en-us/windows/apps/publish/store-policies#1116-live-generative-ai-content),
which requires: (1) Store-metadata disclosure of live generative AI; (2)
Partner Center disclosure during submission; (3) generated content complying
with Store policies; and (4) an in-product mechanism for users to report
inappropriate AI-generated content to the developer.

### Submission checklist (FR-6, PRD §20)

- [ ] **Store description (FR-6.1):** Add a sentence stating that AiFetchly
      uses live generative AI to create content (text, images, templates,
      plans) from user input.
- [ ] **Partner Center disclosure (FR-6.2):** In the submission's
      **Properties** page, check the box / fill the field identifying the
      product's use of live generative AI.
- [ ] **Privacy policy (FR-6.3, §14.10):** The published privacy policy at
      `AIFETCHLY_PRIVACY_POLICY_URL` must describe:
      - what report evidence is sent (the selected AI output snapshot and the
        reporter's optional description);
      - that prompts, other messages, files, AI reasoning, tool arguments,
        attachments, and workspace data are **not** included;
      - optional identity (current authenticated user when available;
        anonymous reporting otherwise);
      - purpose (developer review of reported AI output), access (safety
        reviewers), retention (per the backend PRD), and user controls
        (the report action is voluntary and not paywalled).
- [ ] **Certification notes (FR-6.4):** Provide exact steps and a working
      reviewer account that reaches a reportable AI response — open AI
      Assistant, submit a benign prompt, select **Report AI output**, choose
      **Other**, enter "Microsoft certification test", submit, and record the
      `air_...` reference.
- [ ] **Screenshots (FR-6.5):** Attach screenshots of the per-output action,
      the report dialog, and the success confirmation with the `air_...`
      reference.
- [ ] **Backend queue smoke test:** Confirm `POST /api/ai/content-reports`
      is live in the certification environment and the admin review queue
      shows the submitted report (companion backend PRD).

### In-product reporting mechanism

The in-product report action is implemented per
`docs/prd/ai-content-reporting-prd.md` and `docs/prd/ai-content-reporting-technical-design.md`:

- A **Report AI output** button appears on every accessible user-visible
  AI-generated surface (chat, images, plans, artifacts, email templates,
  keyword sets, automatic replies, website-analysis narratives).
- The dialog sends a bounded evidence snapshot (selected output + optional
  comment, re-encoded image previews ≤1024px / ≤1 MiB, max 3) to
  `POST /api/ai/content-reports` via main-process IPC. It never sends
  prompts, reasoning, attachments, tool arguments, or neighboring messages.
- The handler is **not** AI-gated — reporting remains available when hosted
  AI is disabled or a subscription has expired, and it never consumes AI
  credits.
- A successful submission returns and displays a stable `air_...` reference.
