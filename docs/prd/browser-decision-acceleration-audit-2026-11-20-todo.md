# Browser decision acceleration recheck — November 20, 2026

**The PRD and technical design are not complete.** This audit covers `e11892c59bd30188a6d4fb03521615cc5f6c6831` and the local `console.log` addition at `test/vitest/main/managedBrowser/managedBrowserAiToolService.executeTask.test.ts:317`. Reviewed against the [PRD](browser-decision-acceleration-prd.md), [technical design](browser-decision-acceleration-technical-design.md), and [November 19 recheck](browser-decision-acceleration-audit-2026-11-19-recheck-todo.md). Source references use the reviewed revision. R01–R13 preserve the previous numbering for comparison. “Verify” identifies evidence needed to close the item.

The update makes real progress: normal confirmation dismissal reaches the card, waiting and paused lane transitions are emitted, navigation emits dispatch progress, duplicate receipts are filtered, and nested tasks share the lane’s control ID. It also improves duplicate-value single selection, recovery and verifier generation checks, parent job wait signaling, opt-in read/retry, hosted response correlation, and proxy status and credential metadata. The open items below describe where related paths still diverge or the new behavior introduces a regression.

## P1 — Control, execution, and state correctness

- [ ] **R04 | Separate lane control identity from browser execution identity** (D-FR-08/09, M-FR-07, C-FR-04–08). Nested runner completion terminalizes the enclosing lane (`src/service/browserDecision/BrowserTaskRunner.ts:2279–2290`). Terminal state cannot be reopened (`src/service/AgentTaskControlService.ts:151–170`), but the outer loop can continue (`src/service/AgentRuntime.ts:649–666`). A second execution can fail as `task_completed`; admission also reuses the durable ID and upserts the first record (`src/service/ManagedBrowserAiToolService.ts:2191–2201`, `src/modules/BrowserTaskModule.ts:27–54`, `src/model/BrowserTask.model.ts:26`). Keep one control ID, unique execution/journal IDs, and a single owner for lane terminal state. Verify two sequential executions plus Pause/Resume/Stop between them in a real batch lane. An isolated runner probe confirmed the second execution fails today.
- [ ] **R04 | Bring all control actions and prompts through the same gate** (M-FR-05/07/08, C-FR-01–08/10/12/16). Initial lane and watchdog events omit the live session (`src/service/agentTools/runBrowserTasksTool.ts:578–590,625–647`); sparse updates clear an existing session/goal and controls ignore some failed IPC returns (`src/views/components/aiChatV2/BrowserControlCards.vue:359–366,466–489`). Task-only Pause/Resume can skip the browser; supplied pairs can operate on the browser before validation; unknown Stop/Return Now can report success; primary session controls bypass the task gate (`src/main-process/communication/managed-browser-ipc.ts:257–326,344–475,496–551`). The optional parent mutation guard omits handoff, sign-in, and cache clear (`src/service/ManagedBrowserAiToolService.ts:405–418,1257,2285,2422`). Sign-in dialogs still use the child route; the accelerated bridge drops the structured consequential-action proposal (`:802–811,1414–1450,2307`; `src/service/browserLogin/BrowserCredentialLoginService.ts:403,484,677,834`). Resolve task/session and ownership in main first; route every prompt with parent conversation/task label. Verify first live row, sparse events, queued/count/focus controls, invalid IDs, Stop during an IPC transition, child credential/picker/approval, and parent/sibling isolation.
- [ ] **R06 | Make handover and cleanup authoritative** (M-FR-06–09). Transfer changes ownership even without a matching lease (`src/modules/ManagedBrowserModule.ts:1140–1162`). A rejected stop can bypass cleanup for sibling sessions; callers ignore `failedSessionIds` and can claim release anyway (`src/service/agentTools/runBrowserTasksTool.ts:815,927–967,1025–1026,1236`). Clear Conversation cleanup swallows failures and Clear All does not use it (`src/modules/ManagedBrowserModule.ts:1059–1064`, `src/main-process/communication/ai-chat-v2-ipc.ts:1749–1777`). Require a matching lease, coordinate owner and lease changes with rollback, attempt all cleanup, and preserve unresolved cleanup for retry with truthful results. Verify missing/mismatched leases, failed first stop, late launch and both clear actions.
- [ ] **R07 | Fix receipt access and validate before transfer** (M-FR-02–05/09/11). The batch loop stores externalized results under the control/lane ID (`src/service/AgentRuntime.ts:628`, `src/service/AIChatQueryLoop.ts:4837`) but grants with the generated agent task ID and still returns receipts after a failed grant (`src/service/AgentRuntime.ts:928–965`, `src/modules/ToolResultModule.ts:539–541,585–591`). Batch ownership and terminal decisions precede final normalization (`src/service/agentTools/runBrowserTasksTool.ts:880–1010,1065+`); extracted output is deduped only within each row (`:1293–1298`). Use the verified stored owner for grants, provide only accessible receipts, and validate nested bytes, proposals and retained session evidence before status and transfer. Missing confirmation sink also still permits admission (`:429`); require it and implement the scoped routine-action grant with separate consequential approval. Verify actual parent receipt reads, malformed successes, sibling duplicates, denial/expiry and Stop during handover.
- [ ] **R11 | Finish active/wait clocks, Return Now and restart** (D-FR-10/10a, C-FR-09/11/14, C-AC-03). The watchdog starts after confirmation and samples lane control, so it can miss child-only credential/picker waits (`src/service/agentTools/runBrowserTasksTool.ts:534–602`, `src/service/browserLogin/BrowserCredentialLoginService.ts:421,501,701`). The parent can expire a still-marked wait at the original deadline; repeated set resets the wait start (`src/service/AIChatQueryLoop.ts:6577–6580,6603–6628`, `src/service/ToolJobRegistry.ts:443–451`). Cancellation returns text while Return Now reads structured output; its partial branch only count-caps nested extraction (`src/service/AgentRuntime.ts:743–749,1116–1135`, `src/service/agentTools/runBrowserTasksTool.ts:826–844`). Pause expiry and reconciliation of interrupted parallel lanes still need durable state and lease cleanup. Verify 45-minute waits through the old deadline, staggered waits, single-lane expiry, restart without mutation, and accessible bounded partial results.

## P1 — Decision boundaries and truthful results

- [ ] **R01 | Enforce the admitted provider revision across all paths** (D-FR-01–05/08/09/14/16–19). The new dispatch checks run before awaited service and approval work; `SIGN_IN` and `DONE` branch separately (`src/service/browserDecision/BrowserTaskRunner.ts:873–1082,1261,1511`). Carry provider revision and cancellation through the final mutation/verifier boundary and durable records. Apply the lower of provider and application limits: a reported `maxCandidates:120` can expand the default shortlist of 16 (`:430–437`, `src/service/browserDecision/BrowserCandidateBuilder.ts:62–69`, `DecisionClients.ts:392`, `SystemOneDecisionClient.ts:78` in the same service directory). Enforce candidate-local operations and preserve unsupported/empty/unknown distinctions through fallback. Validate all envelopes before early branches, including combined planner/caller criteria and resume subgoal limits. Verify route changes during journal, sign-in, approval and action preparation, plus slow/missing/explicitly unsupported discovery and limit edges.
- [ ] **R02 | Restore SELECT replacement semantics and live option eligibility** (D-FR-12/15/17, D-AC-04). One page pass now preserves exact option identity for single select; the indexed multi-select branch sets requested options without clearing earlier selections and does not check live disabled options (`src/childprocess/managed-browser/BrowserActionExecutor.ts:213–226`). This affects both legacy and accelerated paths. An isolated probe confirmed requested green leaves red selected. Verify replacement/empty behavior under the declared contract, duplicate values, unsupported/disabled options or groups, missing expectations, and changed/detached targets.
- [ ] **R05 | Observe after every resume and require independent completion evidence** (D-FR-22–26, C-FR-05–08/13, D-AC-07/09). Generation checks improved for delayed recovery and DONE verdicts. The main loop can still reuse cached state at a safe-point resume (`src/service/browserDecision/BrowserTaskRunner.ts:531–611`); same-account verification can rely on cached state, and a changed same-domain URL is insufficient evidence of the requested outcome (`:873–1009`). Invalidate pending observations/decisions on resume, bind verification to fresh state and exact requested criteria/account, and return a truthful partial on ambiguous evidence. Deliver resume instructions to the next active outer query; the current `src/service/AgentRuntime.ts:679–690` callback consumes them to append a transcript entry. Verify safe-point and handoff resume, unrelated in-domain navigation, and late verifier responses.
- [ ] **R10 | Make route probe writes atomic and finish wire contracts** (D-FR-01–04/16–25, D-AC-08/11). The three probe calls use live transport; after the write the comparison rereads saved capabilities instead of the current provider epoch, and awaited preference updates can overwrite intervening changes (`src/main-process/communication/managed-browser-ipc.ts:729–805`, `src/modules/ManagedBrowserSettingsModule.ts:397–453`). Probe one captured model/route; guard persistence against overlapping probes/settings changes. Hosted correlates IDs and revision, but version/model or conflicting echoes still need validation (`src/service/browserDecision/DecisionClients.ts:178–231`); chat structured schema, prompt, parser and fallback also need alignment (`:259–280,442,530–549`). Verify older and unsupported providers, native route/profile and model budgets, same-boundary planning/recovery and accurate usage/cost for failed, retried or canceled requests.
- [ ] **R12 | Bind each recovery request to its actual snapshot and identity** (D-FR-19/22–26). On failed reobserve, recovery reuses the pre-action decision input but returns a post-action bound observation; the old request ID is reused for changed step/text (`src/service/browserDecision/BrowserTaskRunner.ts:1830–1842,1977–2009`). An isolated runner probe confirmed a ref proposed in that path becomes `unknown_target`. Equivalent untargeted failures terminate while targeted failures enter recovery (`:1363–1373,1608–1642`); the progress criterion call still omits extraction (`:1971`). Use a fresh request ID and one matched input/cursor (or report unavailable), semantic failure keys, and consistent progress accounting for extracted data. Verify failed and delayed reads plus equivalent failures in both branches.
- [ ] **R13 | Keep references and command ownership through actual settlement** (D-FR-08/09/10a/15a/26/27, D-AC-05/06). The main pin is one session slot and best effort; the worker acknowledges missing refs, the runner drops its pin before consuming the proposal, and the service attests only the latest snapshot (`src/modules/ManagedBrowserModule.ts:453–480`, `src/childprocess/managed-browser/index.ts:282–290`, `src/service/browserDecision/BrowserTaskRunner.ts:706–712`, `src/service/ManagedBrowserAiToolService.ts:723–752`). Bind approvals to trusted semantic context and exact request, preserve references across passive observes, and keep worker ownership until cancellation settles. Approval redispatch can skip renewed Stop/Pause/generation/deadline checks or outcome journaling if it throws (`BrowserTaskRunner.ts:1328–1366,1556–1594` in the same service directory); nested execution can miss an already aborted signal (`ManagedBrowserAiToolService.ts:680–701,951–964`). Navigation dispatch markers help, but a session-wide flag still cannot settle a specific timed-out command. Verify targeted and untargeted before/after-dispatch failures, rejection, expiry, concurrent reads and zero replay of an uncertain effect.

## P1–P2 — Account, credential, site, and proxy lifecycle

- [ ] **R03 (P1) | Finish defensive credential containment at every output boundary** (A-FR-06/08/15, A-AC-01, D-FR-12). - [ ] **R08 (P1) | Tie rejection to the exact saved credential version** (A-FR-06/09–11/17). The marker persists until replacement on one path; ordinary editor saves and credential-card upsert do not share that rule. Finish the per-account/site attempt ledger, including concurrent sessions and switched-account reservation until fill settlement. Recheck opt-in when a deferred attempt proceeds. Verify all write paths, no-op updates and late outcomes after replacement.
- [ ] **R08 (P1/P2) | Complete cookie-first sign-in, ordered recipes and consent** (A-FR-03/17/20/21, Q-01, design §§13–14). Add Q-01’s one-time existing-account opt-in prompt. Verify restored-valid/stale cookies, switched identity, multi-stage login, immediate post-create state and both detail route variants.
- [ ] **R09 (P1) | Make proxy switch a confirmed, recoverable transaction** (P-FR-01–09, P-AC-01/02). Verify explicit and default selections, downgrade/no-direct-fallback, key rotation, concurrent edits, and rollback on both initial route types. The renderer still lacks start proxy options (`src/views/api/managedBrowser.ts:74–80`, `src/schemas/ipc/managedBrowser.ts:32–38`). Qualify bundled Chromium locale/timezone/WebRTC behavior.
