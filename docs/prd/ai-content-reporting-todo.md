## Should-do

### TODO-5 — Single generated image is not selected by default (FR-2.7, §9.2)

- **Priority:** P0 bug in the shipped Chat V2 image path
- **Why incomplete:** Dialog watch sets `selectedImageIndices` to all indices only when `imgCount > 1`. For one image it initializes to an empty set. Submit then hits “Select at least one image to report.” PRD §9.2: thumbnails with **each image selected by default**.
- **Where:** `src/views/components/aiContentReport/AIContentReportDialog.vue` (`watch` on `modelValue`)
- **Done when:** Opening the dialog selects every available image, including a single image. User may deselect extras when there are multiple, but at least one item must remain selected.

### TODO-6 — Chat V2 report button can appear on empty placeholders (FR-1.2)

- **Priority:** P0
- **Why incomplete:** `isReportableAssistant` in `AiChatV2Message.vue` is `role === "assistant"` + not tool call/result + `status === "idle"`. It does not require non-empty text or generated images. FR-1.2 forbids the action on empty placeholders (legacy chat already requires `content.trim()`).
- **Where:** `src/views/components/aiChatV2/AiChatV2Message.vue`
- **Done when:** Button shows only when the idle assistant message has reportable text and/or generated images. Still hidden for user/system messages, typing, permission prompts, raw tool arguments, errors, and empty placeholders.

### TODO-7 — Dialog focus is not moved or restored (PRD §11.3)

- **Priority:** P0 accessibility
- **Why incomplete:** Title has `id` and `tabindex="-1"` but nothing focuses it on open. Closing does not return focus to the originating **Report AI output** control.
- **Where:** `AIContentReportDialog.vue`; parents that host the dialog (`AiChatV2Messages.vue`, plan card, artifact card/workspace, `AiChatBox.vue`, `ChatInterface.vue`, `templatedetail.vue`)
- **Done when:** Open moves focus to the heading or first field. Close (cancel, overlay, or after the user dismisses success) restores focus to the originating action. Keyboard-only path can open, choose category, note, submit, and close without a pointer.

### TODO-8 — Privacy-policy link is never passed (FR-2.6)

- **Priority:** P1
- **Why incomplete:** Dialog renders the link only when `privacyPolicyUrl` is set. No surface passes that prop, so the link never appears. Reporting must not depend on clicking the link.
- **Where:** `AIContentReportDialog.vue` and every mount site
- **Done when:** A real product privacy-policy URL is passed into the shared dialog on all surfaces. Submit still works if the user never opens the link.

### TODO-9 — Triage metadata missing on secondary surfaces (FR-3.8)

- **Priority:** P1
- **Why incomplete:** Main process fills `appVersion`, `platform`, and `installId`. Chat V2 includes conversation/message/model/timestamp. These surfaces omit model and/or `generatedAt`:
  - Legacy chat (`buildLegacyChatDescriptor` in `AiChatBox.vue`)
  - Knowledge chat (`buildKnowledgeDescriptor` in `ChatInterface.vue`)
  - Email template (`buildEmailTemplateDescriptor` in `templatedetail.vue`)
- **Done when:** Each descriptor supplies model and RFC3339 `generatedAt` when the surface has them. Omitted fields remain optional only when the surface truly has no value.

### TODO-10 — Component, integration, and image-encoder tests (PRD §18.2, §18.4, FR-3.5)

- **Priority:** P0 for AC-10 (“unit, component, IPC, integration, localization, accessibility, and certification tests pass”)
- **Why incomplete:** Worktree has schema, service, error-mapper, and IPC Vitest files only. Missing:
  - Component tests: action visibility, category required, cancel sends nothing, in-flight disable, failure retains fields, success shows `air_...` and **Reported**, plan-card and image branches, keyboard focus
  - Integration tests: Chat V2 bounded payload to a stub backend, re-encoded image with no local path, historical message after `USER_AI_ENABLED=false`, 429 preserves dialog data, six locales render
  - Image-encoder unit tests: reject SVG/HTML/paths/URLs, cap 1024px / 1 MiB / 3 images, `evidenceUnavailable` fallback
  - Localization parity CI check across `en/zh/es/fr/de/ja`
  - Accessibility / 1366×768 / 200% scale certification pass
- **Where:** `test/vitest/utilitycode/` (encoder), `test/vitest/` component tests for the Vue dialog/button, IPC/integration under `test/vitest/main/`
- **Done when:** §18.1–18.4 cases above exist and pass. Encoder behavior is pinned by tests, not only by runtime code.

## Explicitly out of scope (do not add)

These are PRD non-goals or Phase 3. They are **not** incomplete v1 work:

- General support-ticket system, public comments, user-to-user reporting
- Asking the model to regenerate from the report action
- Automatic reports from local classifiers
- Uploading prompts, full conversation, reasoning, attachments, workspace files, or tool results unless that item is the selected output
- Storing reports in desktop SQLite
- Offline report queue
- Promising the reporter an individual response
- Remotely deleting historical local chat output
- Optional report-status lookup, server-provided category help, correlation dashboards, remote artifact invalidation (PRD §16 Phase 3)
