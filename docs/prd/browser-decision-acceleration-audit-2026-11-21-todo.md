# Browser decision acceleration audit — November 21, 2026

**The PRD and technical design are not fully implemented.** Reviewed at `f6d0d1f2a90b12f0c1750353a7091e3f163744d5` (`feature/browser-decision-acceleration`) against [the PRD](browser-decision-acceleration-prd.md) and [the technical design](browser-decision-acceleration-technical-design.md). This pass rechecked the November 20 fix-pass remainder in the current source. It did not re-run the unit suite or live Electron.

Most of the product surface exists: the provider-aware browser gate, `browser_execute_task`, hosted/chat/native decision clients, semantic approvals, unknown-effect handling, the site registry, credential sign-in, proxy selection and switching, `run_browser_tasks`, and pause/take-control/resume/stop. The November 20 fix pass closed the items it marked closed (multi-select replace, recovery snapshot binding, credential-version rejection, receipt owner grants, action-URL containment, lease-transfer rollback, deferred cache clear, execution reopen, resume discard, shortlist cap, and the parent mutation guard). Those are not reopened here.

The open work below is what still diverges from the contract, or is a bug in a path that otherwise looks done.

## P1 — Bugs

- [ ] **B01 | Direct `browser_sign_in` posts the credential card on the hidden child conversation** (A-FR-03/05, M-FR-08). The accelerated runner publishes the card on the root conversation (`src/service/browserDecision/BrowserTaskRunner.ts:1113–1119`). The tool the operator is told to call does not: `ManagedBrowserAiToolService.signIn` passes `context.conversationId` (`src/service/ManagedBrowserAiToolService.ts:2326–2328`), and a sub-agent loop sets that to the hidden `agent-v2` conversation (`src/service/AgentRuntime.ts:622–635`). The account picker and site-confirm card use the same id (`src/service/browserLogin/BrowserCredentialLoginService.ts:403–409,484–487`). The parent chat renders a request only when `request.conversationId` equals the open conversation (`src/views/components/aiChatV2/BrowserControlCards.vue:148–156`). A child-routed card never appears, the in-job wait sits until TTL, and the user cannot submit credentials. Publish every sign-in, picker, and site-confirm request on `rootConversationId`, and keep the submit channel bound to that same id. Verify a sub-agent `browser_sign_in` with no saved account, with several accounts, and with an extra-domain proposal; the parent chat must show the card and a submit must resolve the wait.

- [ ] **B02 | Credential and account-picker waits do not freeze active time or the parent poll** (D-FR-10a, C-FR-09, C-AC-03). Handoff does this through `HandoffCoordinator.beginIntervention` (`src/service/browserAgents/HandoffCoordinator.ts:89`). The credential service only calls `ToolJobRegistry.setUserWait` when a `jobId` is present (`src/service/browserLogin/BrowserCredentialLoginService.ts:420–422,500–502`) and never calls `AgentTaskControlService.beginIntervention`. The runner’s `signIn` dependency does not pass a job id (`src/service/browserDecision/BrowserTaskRunner.ts:1113–1120`; wrapper at `src/service/ManagedBrowserAiToolService.ts:2036–2042`). The batch watchdog treats a lane as waiting only when the control record is `waiting_for_user` or `paused` (`src/service/agentTools/runBrowserTasksTool.ts:566–567`). The child runtime clock asks `isUserWaiting` with the hidden conversation id (`src/service/AgentRuntime.ts:596`). With no job flag and no control state, a credential or picker wait inside `browser_execute_task` counts as active time and can expire the parent poll. Mark the lane `waiting_for_user` for the whole card wait, pass the parent job id, and clear both on resolve, cancel, and handoff. Verify a wait longer than the child active budget and the parent poll deadline; only that lane should stay alive, and a sibling should still finish.

- [ ] **B03 | Resume instructions are consumed twice and one consumer loses them** (C-FR-07). `consumeResumeInstructions` deletes the text (`src/service/browserAgents/AgentTaskControlService.ts:372–377`). Both the sub-agent pause wait (`src/service/AgentRuntime.ts:679–688`) and the nested runner safe point (`src/service/browserDecision/BrowserTaskRunner.ts:557–560`) consume the same control id, because `executeTask` adopts `ownerAgentId` as `taskId` (`src/service/ManagedBrowserAiToolService.ts:1842–1848`). Whichever resumes first keeps the text. The other gets null: either the agent transcript omits the user’s instructions, or the next decision subgoal does. Deliver the note once to both the agent transcript and the runner’s next decision input without a second consume. Verify Pause → “Resume with instructions” on a batch lane that is inside `browser_execute_task`; both the next model turn and the next decision must contain the same text, and a second resume must not replay it.

- [ ] **B04 | A failed proxy switch from a direct session cannot roll back** (P-FR-02, P-AC-01). After `stop`, a failed `start` restores only when `effectiveProxyId` is non-null (`src/modules/ManagedBrowserModule.ts:2720–2734`). A direct session stores `effectiveProxyId: null` (`src/modules/ManagedBrowserModule.ts:806–810`). The restore then throws `proxy_switch_restore_failed` / `restore_proxy_unknown` and leaves the browser stopped. A failed proxied restore is also swallowed: the inner `catch` at `:2752–2754` discards the restore error and rethrows only the start error, so the caller cannot tell that rollback failed. Restart the previous route, including `direct`, and return a result that names both the switch failure and the rollback outcome. Verify direct→bad-proxy and proxy→bad-proxy, including a restore that itself fails.

- [ ] **B05 | Proxy switch drops the parent conversation** (M-FR-07/08, P-FR-02). The new session is started with `conversationId` and `agentTaskId` only (`src/modules/ManagedBrowserModule.ts:2700–2713`). `start` sets `rootConversationId` only from `input.rootConversationId` (`src/modules/ManagedBrowserModule.ts:794`), which the switch never passes. Notices then publish on the hidden child conversation (`src/modules/ManagedBrowserModule.ts:2025–2026`). Copy `rootConversationId` (and the previous owner pair) onto the replacement session, and roll that pair back with the route. Verify a sub-agent switch: the parent chat still receives the session card, challenge notice, and credential card.

- [ ] **B06 | The account editor can change platform without rebinding `site_id`** (S-FR-06, A-FR-03/07). The detail form submits `social_type_id` and does not send `site_id` (`src/views/pages/socialaccount/socialaccountdetail.vue:581–590`). `saveSocialAccount` writes `social_type_id` and leaves `site_id` as stored (`src/modules/socialAccountModule.ts:252–254`). Sign-in matching is `site_id = :siteId OR social_type_id = :platformId` (`src/model/SocialAccount.model.ts:149–152`), and credential lookup falls back to `social_type_id` when `site_id` is null (`src/modules/socialAccountModule.ts:496–500`). An edited account can match the old site and the new platform at once, and a password decrypt can trust the stale site. Make a platform change an explicit rebind of `site_id`, credentials, and cookie domain policy, and match on one authoritative id. Verify a seeded account moved to another seeded site, a legacy null `site_id` row, and a high-id AI site.

## P1 — Unfinished requirements

- [ ] **R01 | Batch confirmation fails open, and there is no expiring routine-action grant** (M-FR-04). `requestBatchConfirmation` returns `true` when no renderer sink is registered (`src/service/agentTools/runBrowserTasksTool.ts:429–431`). The confirm result is only a boolean (`:506`); nothing records a grant of observe/navigate/click/fill/select scoped to those agent tasks and expiring with the batch. Routine clicks are globally `auto` today (`src/service/BrowserActionRiskClassifier.ts:210–215`), so the missing grant is invisible until a future policy tightens them. Require a sink in product runs, and record a batch-scoped routine grant that consequential actions cannot use (M-FR-05 stays a separate `needs_user`). Verify a missing sink refuses the batch, a denial starts zero sessions, and a grant dies when the batch ends.

- [ ] **R02 | Account contention is one short retry, not a queue** (M-FR-06). A second task for a busy account polls the lease for about 8 seconds (`src/service/agentTools/runBrowserTasksTool.ts:728–743`, `busyQueueWaitMs ?? 8_000`) and then fails. The PRD requires the second task to wait, not fail, for the account’s session. Queue until the holder releases, the batch is cancelled, or the task’s own active budget ends. Verify two tasks on one account where the first holds the lease longer than 8 seconds; the second must start after release, and Stop during the queue must not start it.

- [ ] **R03 | No per-provider concurrency or batch token/cost budget** (M-FR-10). Decision calls back off on a 429-shaped error inside one client (`src/service/browserDecision/DecisionClients.ts:420–425`). `runBrowserTasks` has no shared provider concurrency limit, no batch token/cost ceiling, and no executor-level 429 backoff. Parallel lanes can stampede one custom endpoint. Add a per-provider in-flight cap and a batch budget that stops remaining lanes with a truthful partial. Verify three lanes against a provider that returns 429 on the second concurrent call.

- [ ] **R04 | The batch executor is not selectable, and there is no sub-agent model** (M-FR-12, settings §7). `runBrowserTasks` always calls `agent-browser-operator` (`src/service/agentTools/runBrowserTasksTool.ts:657–666`). The operator may call `browser_execute_task` (`src/service/AgentDefinitionRegistry.ts:148–150`), but the batch tool has no `llm_agent` / `fast_runner` switch. Settings expose `chatDecisionModel` for the decision route (`src/views/components/settings/ManagedBrowserSettingsPanel.vue:150`) and no separate sub-agent model. Add both controls, and for a custom provider require the sub-agent model to be a real model on that same endpoint. Verify a batch forced onto `fast_runner`, and a custom provider whose sub-agent model differs from the planner model.

- [ ] **R05 | Occluded-window throttling, window title, and tiling are missing** (M-FR-13, C-FR-15). Launch args set size, language, and WebRTC UDP policy when a proxy is present (`src/childprocess/managed-browser/BrowserFingerprintPolicy.ts:197–222`). They do not disable occlusion-based backgrounding, do not set “AI is controlling this window” on the window title, and do not offset or tile concurrent windows. Unexpected page changes do not auto-pause. Add the Chromium flag, title, and layout, and keep them compatible with the fingerprint self-test. Verify two concurrent headed windows on the bundled Chromium: both stay responsive while covered, titles name the AI, and the windows do not stack on the same origin.

- [ ] **R06 | Handoff dialogs are not queued** (C-FR-10). Each session card opens its own handoff dialog whenever the session is in a handoff-like state (`src/views/components/aiChatV2/ManagedBrowserSessionCard.vue:439–446`). There is no “N tasks need you” badge and no one-at-a-time queue. The app also has no automatic-focus steal, which matches the PRD; the queue does not. Show one dialog, badge the rest, and keep “Open browser” as the only focus change. Verify two lanes hitting CAPTCHA together.

- [ ] **R07 | Registrable-domain identity is a curated suffix list** (S-FR-03, A-FR-02). `src/service/browserDecision/RegistrableDomain.ts` documents that `tldts` is not installed and ships a hand-maintained subset. Unknown multi-label suffixes fall back to the last label. A public suffix missing from that set collapses unrelated hosts into one registrable domain and can release a stored password across them. Use a maintained public-suffix list, keep the private-suffix cases already in the file, and reject a suffix that the list does not classify. Verify `attacker.github.io` versus `victim.github.io`, a country suffix absent from the current set, and an IP/HTTP URL.

- [ ] **R08 | Cookie refresh still prefers the static platform manifest** (S-FR-05/06). `handleRefreshedCookies` uses `getPlatformManifest(platformId)` first and the registry only when that returns nothing (`src/modules/ManagedBrowserModule.ts:1785–1789`). A seeded site whose registry allowed-domains differ from `PLATFORM_SESSION_MANIFEST` persists cookies under the static list. Launch/bind should use the same source. Prefer the registry, and use the manifest only as a seed. Verify a seeded site whose registry suffix list is narrower than the static manifest: a cookie for the extra static suffix must not be stored.

- [ ] **R09 | Existing accounts have a per-account switch, not the one-time opt-in prompt** (Q-01). The detail page edits `ai_use_enabled` (`src/views/pages/socialaccount/socialaccountdetail.vue:57–62`). Nothing lists pre-feature accounts once and asks the user which of them AI may use. Add that prompt, defaulting every existing account to off until the user confirms. Verify a database that already has accounts: first launch shows the list, declining leaves sign-in with `account_not_eligible`, and a later detail-page toggle still works.

- [ ] **R10 | The renderer cannot choose a proxy when it starts a session** (P-FR-01, P-FR-09). `startManagedBrowser` accepts account, purpose, URL, and conversation only (`src/views/api/managedBrowser.ts:74–80`). The IPC schema matches (`src/schemas/ipc/managedBrowser.ts:32–38`). The model tool accepts `proxy_id` / `auto` / `direct` (`src/config/skillsRegistry.ts:4967`). The session card already shows a proxy label (`src/views/components/aiChatV2/ManagedBrowserSessionCard.vue:18–19`). Add the same selection to the user-started session path, including the account-proxy confirmation. Verify start with an explicit proxy, `auto` plus country, and `direct` on an account that already has a linked proxy.

- [ ] **R11 | Capability probes can overwrite each other** (D-FR-18, D-AC-08, design §9.2). The probe captures a revision, writes capabilities, then compares the saved capability revision with the revision it captured (`src/main-process/communication/managed-browser-ipc.ts:724–803`). Two overlapping probes, or a settings save that lands inside `updatePreferences`, are last-write-wins. The hosted client checks id and `schema_version` echoes (`src/service/browserDecision/DecisionClients.ts:171–235`) and does not check the echoed model. Serialize probes on one captured provider snapshot, and reject a hosted result whose echoed model or contract version disagrees. Verify two probes in flight and an older server that omits `model`.

- [ ] **R12 | Restart marks tasks interrupted in memory only** (D-FR-10, C-FR-14). IPC registration sweeps in-memory control records and durable task rows (`src/main-process/communication/managed-browser-ipc.ts:125–140`). Leases and workers do not survive the process, but a row left `running` with a live lease token is not reconciled against “no process,” and parallel lanes have no durable partial bundle to show after restart. Persist the interrupted partial, release any recorded lease, and do not replay a mutation. Verify kill-and-relaunch during a two-lane batch and during an open credential card.

## Fix pass — November 21, 2026 (implementable items closed)

One commit per logical unit, all with tests where the path is unit-testable.

- **R11** — overlapping capability probes serialize on one chain (each captures its revision when it starts; last-verified-wins). The hosted model echo check is deferred with E04/Q-05 — the decision envelope carries no client-requested model to compare against.
