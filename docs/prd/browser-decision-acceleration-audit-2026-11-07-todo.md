## Current defects found by tracing production calls

- [ ] **P0 — serialize runner admission before the first await.** ManagedBrowserAiToolService.ts checks runnerOwnedSessions at line 1143 but records ownership only at line 1379, after asynchronous admission. Two requests can both see the session as free and later start separate runners. A later set overwrites the first owner. Reserve synchronously, release on every early return and exception, and enforce ownership on ordinary browser mutation tools throughout the runner lifetime. Test two overlapping admissions with a barrier, rejected admission followed by retry, and a legacy action between runner steps. D-FR-08, M-AC-02.
- [ ] **P0 — require durable intent before browser input.** ManagedBrowserAiToolService.ts:1323 supplies persistActionIntent but catches storage rejection and resolves normally. BrowserTaskRunner awaits an apparent success and can dispatch a mutation without its durable intent. Adjacent cursor and outcome writes also suppress failures. Fail before dispatch when intent cannot be recorded, preserve unknown effects after dispatch, and surface persistence failure in the terminal result. Test database errors at each write and restart between intent, effect and outcome. D-FR-07/09/10/26, design §§6–7.
- [ ] **P1 — complete account binding only after the worker acknowledges it.** ManagedBrowserModule.ts:1810 sets the account identity and authenticated flag before asynchronous account lookup and BIND_PLATFORM. A missing manifest skips the command. A worker rejection or timeout at line 1837 is swallowed, then the module publishes success. A lookup exception leaves partially committed state. Coordinate lease transfer, worker acknowledgement, cookie capture and main record publication, including retry after an uncertain response. Exercise missing account, missing manifest, dead worker, lost acknowledgement, and cookie capture failure. A-FR-11/13, C-FR-13.
- [ ] **P1 — route and retain batch controls per conversation and batch.** runBrowserTasksTool.ts:233 emits started with batchId alone. managed-browser-ipc.ts:145 sends the event to the renderer window. BrowserControlCards.vue subscribes without a conversation filter and stores only one activeBatch. Starting B while A runs replaces A, and later A updates are discarded. Switching chats can expose another chat's rows or lose the active controls. Include root conversation identity, retain multiple batches, restore state on mount, and resolve control targets authoritatively in main. Test two overlapping batches, two chats, remount, Stop and Return now independently. M-FR-03/08, M-AC-03, C-FR-04/10–12.
- [ ] **P1 — recover controls beyond the observation scan window.** BrowserObservationService.ts:93 slices the raw node list before checking visibility. Visible-first ordering helps only within that slice. A page with SCAN_CAP hidden controls before its only visible button still yields no actionable button. Reobserving with the same scan start cannot recover it. Add bounded continuation or prioritization of focused/dialog controls and test beyond the boundary with hidden, offscreen and disabled predecessors. D-FR-12–15a.
- [ ] **P1 — preserve native SELECT values.** BrowserObservationService.ts:147 truncates the native option value to 200 characters before the runner resolves o_N. Selecting an option whose value exceeds the limit therefore passes a different value to the browser. Two values sharing the same prefix become indistinguishable. Keep display labels bounded and retain exact option identity inside the worker. Check actual selected state, duplicate labels, long values, disabled choices and DOM change before execution. D-FR-16/17, D-AC-04.
