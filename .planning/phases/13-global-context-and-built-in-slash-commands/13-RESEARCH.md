# Phase 13: Global Context and Built-in Slash Commands - Research

**Researched:** 2026-07-04
**Domain:** Electron main-process config loading, AIChatV2 context injection, slash command registry + composer UI
**Confidence:** HIGH

## Summary

Phase 13 is the foundation of the v2.0 Local Extensibility milestone. It adds a global `~/.aifetchly` config loader, injects `AGENTS.md` into the AiChatV2 system message, and ships a slash command registry with four built-in commands (`/help`, `/clear`, `/status`, `/reload-config`) plus a renderer suggestions UI. The phase is **greenfield for its core surfaces** (no existing `CommandRegistry`, `SlashCommandParser`, or `.aifetchly` loader exists — confirmed by grep) but **plugs into well-established existing patterns**: the `AIChatContextAssembler`, the `_shared/registerValidatedHandler` IPC wrappers, the `channellist.ts` + `views/api/*.ts` + `preload.ts` IPC triangle, and the `contactExtraction`/`aiChatV2` i18n group shape.

The technical design doc (`docs/prd/aifetchly-local-extensibility-technical-design.md`) is exhaustive and authoritative — it specifies the file map, data contracts, registry API, lookup order, startup sequence, and channel names. This research confirms the design's assumptions against the actual codebase and extracts the **concrete signatures, file paths, and insertion points** the planner needs. Two important refinements surfaced: (1) `js-yaml` ^4.1.0 is an existing dependency but **must NOT be used** for frontmatter parsing (CFG-07 mandates a tag-safe hand-rolled parser because workspace files are untrusted); (2) the cleanest way to honor TRS-05 (AI-gate only AI-serving dispatch) is to have `slash-command:dispatch` return `submit_prompt` and let the **existing** `AI_CHAT_V2_STREAM` path enforce `USER_AI_ENABLED` — avoiding a duplicated gate.

**Primary recommendation:** Build `CommandRegistry` as a class (mirroring `FilePathGuard`/`SkillDiagnosticsService`), wire `AGENTS.md` injection into `AIChatContextAssembler.assemble()` right after the custom-context-directive block (line ~128), add slash IPC via the existing `registerValidatedHandler` wrapper (NOT `registerAiValidatedHandler` — see TRS-05 analysis), and fire the initial `~/.aifetchly` scan alongside `SkillImportService.loadPersistedSkills()` at `background.ts:357`. Phase 13 installs **zero new packages** — all stdlib (`fs.promises`, `crypto`, `os.homedir`, `path`) plus already-present deps (`zod ^3.24.0`, `picomatch ^4.0.2`).

### Pattern 3: Registry with Defensive Copies + Source Replacement (CMD-01)
**What:** Registry returns copies (immutability); `replaceSource` reconciles add/change/delete/rename atomically.
**When to use:** `CommandRegistry`, and (phase 16) the refactored `AgentDefinitionRegistry`.
**Example:**
```typescript
// Source: [CITED: design 7.1, 7.3] + [VERIFIED: codebase — AgentDefinitionRegistry defensive-copy pattern]
export class CommandRegistry {
  private byId = new Map<string, SlashCommandDefinition>();
  private byName = new Map<string, SlashCommandDefinition>(); // first-enabled-wins per lookup order
  private sourceIndex = new Map<string, Set<string>>();       // sourceId -> set of command IDs

  register(cmd: SlashCommandDefinition): void {
    this.byId.set(cmd.id, { ...cmd });
    this.rebuildNameIndex(); // re-applies lookup order: built-in > workspace > user > plugin
  }

  replaceSource(sourceId: string, commands: readonly SlashCommandDefinition[]): void {
    // Atomic reconciliation: delete old source entries, insert new, rebuild name index.
    // Handles delete/rename/missed-events correctly (design 7.3, 10.1).
    const existing = this.sourceIndex.get(sourceId);
    if (existing) for (const id of existing) this.byId.delete(id);
    const next = new Set<string>();
    for (const c of commands) { this.byId.set(c.id, { ...c }); next.add(c.id); }
    this.sourceIndex.set(sourceId, next);
    this.rebuildNameIndex();
  }

  list(): SlashCommandDefinition[] { return [...this.byId.values()].map((c) => ({ ...c })); }
  // listViews() omits full prompt body (renderer-safe) per design 5.5
}
```

### Pattern 4: Restricted Frontmatter Parser (CFG-07) — hand-rolled, NOT js-yaml
**What:** Parse only the initial `---` block; scalars + string arrays only; fail closed; preserve body exactly.
**When to use:** `commands/*.md` (phase 15) and `agents/*.md` (phase 16). Phase 13 builds the parser but only needs it for settings pass-through; commands/agents land later.

### Anti-Patterns to Avoid
- **DON'T use `js-yaml`/`gray-matter` for frontmatter** — tag execution is unsafe for untrusted workspace files. Hand-roll per CFG-07. [CITED: design 6.6]
- **DON'T wrap `slash-command:dispatch` in `registerAiValidatedHandler`** — it would gate `/help`, `/status`, `/reload-config`, `/clear` behind AI-enable, violating TRS-05 ("list/status/reload-rescan handlers do not" need the gate). Use `registerValidatedHandler` and gate only the `submit_prompt` path downstream. See Pitfall 1.
- **DON'T read `~/.aifetchly` from the renderer** — TRS-07 violation. All FS access via main-process IPC.
- **DON'T use Electron `app.getPath('userData')` for the config root** — CFG-01 mandates `os.homedir() + "/.aifetchly"`. userData is for app-managed data, not user-editable config.
- **DON'T patch individual commands on file events** — use `replaceSource` from a fresh full snapshot (design 7.3, 10.1). Patching misses deletes/renames/atomic-saves.
- **DON'T block app launch on the global scan** — fire it async alongside `SkillImportService.loadPersistedSkills()` (background.ts:357). [CITED: design 19.1]
- **DON'T put the watcher worker in `src/modules/`** — phase 14's worker goes in `src/childprocess/aifetchly-config/` per CLAUDE.md. Phase 13 has no worker.
- **DON'T implement `$ARGUMENTS` expansion** — that's CMD-06, phase 15. Phase 13 built-ins are local-only (no prompt expansion needed).

## Common Pitfalls

### Pitfall 1: Wrong AI-Gate Placement for Slash Dispatch (TRS-05)
**What goes wrong:** Wrapping `slash-command:dispatch` in `registerAiValidatedHandler` breaks `/help`, `/status`, `/reload-config`, `/clear` when `USER_AI_ENABLED !== "true"`.
**Why it happens:** CLAUDE.md says "AI feature IPC handlers MUST check AI enable first" — easy to over-apply.
**How to avoid:** TRS-05 explicitly states "list/status/reload-rescan handlers do not" need the gate, and built-in commands are local. Two valid strategies:
  - **Strategy A (recommended):** `slash-command:dispatch` uses `registerValidatedHandler` (no AI gate). For prompt commands it returns `action: "submit_prompt"`; the renderer submits that prompt through the EXISTING `AI_CHAT_V2_STREAM` channel, which ALREADY checks `USER_AI_ENABLED` via the V2 stream path. No duplicated gate.
  - **Strategy B:** Dispatcher itself checks `Token.getValue(USER_AI_ENABLED)` only when the resolved command `type === "prompt"`; built-ins bypass.
  Either works; Strategy A is DRY. Document the choice in the IPC handler.
**Warning signs:** A test where `USER_AI_ENABLED="false"` and `/status` returns `status:false`. [CITED: design 14.1, 11.4] [VERIFIED: registerValidatedHandler.ts fail-closed logic]

### Pitfall 2: Using `js-yaml` for Frontmatter (CFG-07 violation)
**What goes wrong:** `js-yaml`'s default schema executes YAML tags (`!!js/function`, `!!python/object`), enabling code execution from untrusted workspace files.
**Why it happens:** `js-yaml` ^4.1.0 is already a dep; it's tempting to reuse.
**How to avoid:** Hand-roll `parseRestrictedFrontmatter` — scalars + string arrays only, fail closed on anything else. If a future phase needs richer YAML, load js-yaml with `DEFAULT_SAFE_SCHEMA` (not `DEFAULT_FULL_SCHEMA`) AND validate with zod — but phase 13 keeps it simple.
**Warning signs:** Any `import * as yaml from "js-yaml"` in `AIFetchlyConfigMarkdown.ts`.

### Pitfall 3: Forgetting to Add Channels to BOTH preload Whitelists
**What goes wrong:** `slash-command:list` works but `AIFETCHLY_CONFIG_CHANGED` never reaches the renderer (silent no-op).
**Why it happens:** `preload.ts` has TWO separate whitelists — `invoke.validChannels` (~line 540) and `receive.validChannels` (~line 393). Plus `removeListener` has its own.
**How to avoid:** Add `SLASH_COMMAND_LIST`, `SLASH_COMMAND_DISPATCH`, `AIFETCHLY_CONFIG_RELOAD`, `AIFETCHLY_CONFIG_STATUS` to the `invoke` whitelist; add `AIFETCHLY_CONFIG_CHANGED` to the `receive` whitelist (and `removeListener`'s, which mirrors `receive`). [VERIFIED: preload.ts lines 333-543]

### Pitfall 4: Enter Key Conflict in Composer (CMD-05)
**What goes wrong:** Pressing Enter to choose a slash suggestion also sends the message (because `onKeydown` calls `onSend` on Enter).
**Why it happens:** Current `AiChatV2Composer.vue` line 62-67: Enter (no Shift) unconditionally sends.
**How to avoid:** When the suggestions dropdown is open and an item is highlighted, intercept Enter/Tab to CHOOSE the suggestion and `event.preventDefault()` — do NOT fall through to `onSend`. Keep Shift+Enter as newline. Only bare Enter when no dropdown/selection sends.
**Warning signs:** Selecting a command sends two messages.

### Pitfall 5: `replaceSource` Name-Index Desync
**What goes wrong:** After `replaceSource`, `getByName("review")` returns a stale entry or null.
**Why it happens:** The name index (`byName`) must be rebuilt whenever any source's commands change, applying the lookup order (built-in > workspace > user > plugin).
**How to avoid:** `replaceSource` always calls `rebuildNameIndex()` at the end. Test with table-driven cases covering same-name-different-source. [CITED: design 7.1]

### Pitfall 6: Blocking the Main Process On Startup Scan
**What goes wrong:** App launch stalls while reading `~/.aifetchly`.
**Why it happens:** Synchronous FS APIs or awaiting the scan before restoring the window.
**How to avoid:** Fire-and-forget the scan (`.catch()` logging) alongside `SkillImportService.loadPersistedSkills()` at background.ts:357. `assemble()` must tolerate an empty cache (return `[]` if manager not ready — design 12.3). [CITED: design 16.1, 19.1]

### Pitfall 7: AiChatBox.vue is 1800+ Lines (STATE.md blocker)
**What goes wrong:** Editing the wrong chat component or duplicating logic.
**Why it happens:** There are TWO chat components — legacy `src/views/components/aiChat/AiChatBox.vue` (1800+ lines, STATE.md blocker) and the current `src/views/components/aiChatV2/AiChatV2.vue`.
**How to avoid:** Phase 13 touches ONLY `aiChatV2/` components (`AiChatV2.vue`, `AiChatV2Composer.vue`). Do NOT modify `AiChatBox.vue`. [VERIFIED: STATE.md blocker + aiChatV2/ dir listing]

## Security Domain

### Applicable ASVS Categories

| ASVS Category | Applies | Standard Control |
|---------------|---------|-----------------|
| V2 Authentication | no | n/a (phase 13 adds no auth; relies on existing `Token`/`USER_AI_ENABLED`) |
| V3 Session Management | no | n/a |
| V4 Access Control | **yes** | Trust model: global `~/.aifetchly` enabled-by-default (user-owned); workspace requires approval (phase 14). Built-in commands have no trust gate. [CITED: design 12.1] |
| V5 Input Validation | **yes** | zod for `settings.json` (CFG-03); restricted frontmatter parser (CFG-07); path-safety helper (CFG-05); size limits (CFG-04); SlashCommandParser input rules (CMD-02). **Never trust external file content.** |
| V6 Cryptography | partial | SHA-256 content hashing only (CFG-06) — integrity, not secrecy. No new crypto. Existing `Token`/safeStorage handles secrets. |
| V7 Error Handling | **yes** | Expected failures -> diagnostics (not crashes); unexpected failures -> recoverable source-level diagnostics (design 15.1). Built on existing `try/catch + console.error` pattern. |
| V8 Data Protection | **yes** | Renderer never sees raw file contents except via explicit preview APIs (design 14.2). `SlashCommandView` omits full prompt body. Secret patterns: reuse `PluginDiagnosticsService.SECRET_PATTERNS` if previewing. |
| V13 API & Web Service | **yes** | All renderer access via IPC handlers (preload whitelist). No renderer FS access (TRS-07). |

### Known Threat Patterns for Electron + Local Config

| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| Prompt injection via workspace AGENTS.md | Spoofing / Tampering | Label injected blocks clearly ("User global AiFetchly instructions..."); never word as higher-priority than app system prompt; external web/attachment content cannot override trust (design 12.3). [CITED: design 12.3] |
| Path traversal in config declarations (e.g. `../../../etc/passwd`) | Tampering / Info Disclosure | `resolveConfigRelativePath` rejects absolute, `..`, escaping symlinks (CFG-05). Mirror `FilePathGuard` pattern. |
| Oversized file DoS (256KB+ AGENTS.md) | DoS | Size limits enforced via `fs.stat` before `fs.readFile` (CFG-04); oversized -> diagnostic + ignore. |
| Malicious YAML tag execution (`!!js/function`) | Code Execution | Hand-rolled frontmatter parser; NO js-yaml default schema (CFG-07, Pitfall 2). |
| Workspace repo silently enabling commands | Elevation of Privilege | Workspace requires approval (phase 14 binary trust gate; per-capability trust in phase 17). Phase 13 built-ins are always-on (no workspace origin). [CITED: design 13.1] |
| Renderer reading private file contents | Info Disclosure | `SlashCommandView` excludes full body; list responses are metadata-only (design 5.5, 14.2). TRS-07 boundary test enforces no renderer FS access. |
| Direct execution of arbitrary JS/shell from `.aifetchly` | Code Execution | Phase 13 built-ins are local text only; prompt commands (phase 15) are text-expansion only (TRS-06). No `eval`/`child_process` in the dispatch path. |
| AI-feature bypass when `USER_AI_ENABLED=false` | Abuse | `Token.getValue(USER_AI_ENABLED)` check; fail-closed in `registerAiValidatedHandler` (existing). Phase 13 gates only AI-serving dispatch (TRS-05, Pitfall 1). |

The CLAUDE.md rule "AI feature IPC handlers MUST check AI enable first" interacts subtly with TRS-05's "list/status/reload-rescan handlers do not":

| Handler | AI-Gated? | Mechanism |
|---------|-----------|-----------|
| `slash-command:list` | NO | `registerValidatedHandler` |
| `aifetchly-config:status` | NO | `registerValidatedHandler` |

| `slash-command:dispatch` -> built-in (`/help`, `/clear`, `/status`, `/reload-config`) | NO | returns `show_result`; no AI call |
| `slash-command:dispatch` -> prompt command (phase 15) | YES (downstream) | returns `submit_prompt`; renderer submits via `AI_CHAT_V2_STREAM` which gates `USER_AI_ENABLED` |
